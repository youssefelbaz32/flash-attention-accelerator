QKᵀ Engine — Parallel Architecture

Four dot4 units compute a whole row of the score matrix at once: the same Q row is broadcast to all four, each pairs it with a different K row. The controller iterates over the N query rows, so the whole matrix takes N passes instead of N·N.

data path (Q8.8 buses) control path (FSM / handshake)

One dot4 per column, all fed the same q_mem[row_i] and a distinct k_mem[j], so a full score row is produced per pass. The controller issues when every unit is ready (&d4_in_ready) and captures when every unit is done (&d4_out_valid). Each result is scaled by 1/√d, which is a right shift >>> SQRTD_SH because the dims are powers of four. Trade-off: 4× the multipliers/DSPs for 4× the throughput versus one time-multiplexed unit.
